# DSA-123 — Foundation choices of 2026-11-26 in the code

## Goal
On 2026-11-26 the design owner chose, in Figma previews with light and dark modes, five foundation
changes. The tokens are on `v/5.0.0` in the same push as this task. Most of them reach the code by
themselves, because the code already reads the changed token. This task lists what changes on screen
and the few places where the code must start reading a token.

## What changed in the tokens (on v/5.0.0 in the same push as this task)
| Token | Before | Now | Reaches the code by itself? |
|---|---|---|---|
| `radius/overlay-anchored` (new) | — | `core/radius/400` (8) | — |
| `popover/radius`, `hover-card/radius`, `date-picker/panel-radius`, `popconfirm/radius` | `core/radius/600` (14) | `radius/overlay-anchored` (8) | yes |
| `dropdown/panel-radius` (nph-dropdown-menu, nph-context-menu, nph-menubar), `sidebar/flyout-radius` | `core/radius/500` (12) | `radius/overlay-anchored` (8) | yes |

`design.md` (radius table, `radius/overlay-anchored`, `radius/container`, `radius/overlay`,
`focus/halo-error`, `status/on-solid`, `dropdown/*`) and the `origin` of `semantic.tokens.json` say why.

## What changes in the code
- `src/components/nph-button/nph-button.css`, line 143: the primary type sets
  `--_focus-border: var(--nph-color-primary)`. Read `--nph-button-primary-focus-border` instead (the
  secondary, line 147, already reads `focus/border`). In dark mode the border goes from 2.45:1 to 7.43:1
  over the background in the Gerencial brand; in light mode five brands move one tone.
- The icon-only button is drawn by the same `nph-button.css`; with line 143 fixed it follows. If the
  icon-only primary needs its own hook, it reads `--nph-icon-button-primary-focus-border`.
- `src/components/nph-togglebutton/nph-togglebutton.css`, line 37: read `--nph-togglebutton-focus-border`
  instead of `--nph-color-primary`.
- `src/components/nph-navigation-menu/nph-navigation-menu.css`, lines 178 and 193, already paint the
  focus border with `--nph-focus-border`, the same color; reading `--nph-navigation-menu-focus-border`
  instead keeps the component on its own token (rule T9).
- `src/components/nph-select/nph-select.css`, line 209, and `src/components/nph-combobox/nph-combobox.list.css`,
  line 30: the list reads `--nph-select-panel-radius` and `--nph-combobox-panel-radius` instead of
  `--nph-radius-container` (same value, 8 px; the list now follows the anchored layers).
- `src/components/nph-label/nph-label.css` (the asterisk, comment at line 41) and the asterisk of
  nph-field: read `--nph-label-required-foreground` instead of `status/error`. Same color; in dark mode it measures 6.30:1 over the background and 5.19:1 over the card.
- `src/components/nph-calendar/nph-calendar.css`, line 82: `.title-text` (the year range, the title that
  is not a button) paints `--nph-color-secondary-foreground`. Figma draws it in `color/foreground`; read
  `--nph-calendar-title-foreground`.
- Nothing to do for the other rows: the code reads those tokens already. The panels of nph-popover,
  nph-hover-card, the nph-date-picker, nph-popconfirm, the menus and the nph-sidebar flyout go from 14 or
  12 px to 8 px; the item of nph-dropdown-menu and nph-context-menu goes from 8 to 4 px.

## What Figma draws (2026-11-26)
The variables above are bound in Figma: the lists `1357:137` (nph-select) and `1359:141` (nph-combobox),
the asterisk of `nph-label` `374:6` and of `nph-field`, the year range `3093:2163` and `3093:2218`, and
every panel listed. The previews of the choices are on the Rascunho page `988:6952`: 8439:82450 (radius),
8438:267496 (error halo), 8438:260548 (primary focus), 8241:2 (text on help solid).

## How it is proved
- Stories in light and dark: the focus of the primary button, the primary icon-only button, the
  togglebutton and the navigation menu trigger use the focus color; the error field in focus shows the
  darker halo in dark mode; the text on the help solid reads dark in dark mode; every anchored panel has
  an 8 px corner and the menu item a 4 px corner.
- `npm test`: the token contract tests follow the new values.

## What this task does not do
It does not create or change a token. It does not change Figma. It does not touch the nph-sidebar
flyout items, which keep `sidebar/item-radius` (12) inside the 8 px panel; that fit is an open question
for the design owner.
