# DSA-116 — Update the two tests that pin the old gray ratios

## Goal
The two tests below expect the ratios that the slate tokens give today and pass on `v/5.0.0`, and the spec, the metadata and the Docs page of the same pieces say the same figures.

## What changes
| File and line | Today | What the test expects after this task |
|---|---|---|
| `src/components/nph-tooltip/nph-tooltip.test.ts:2017` (title of the test at line 2010) | `toBeCloseTo(scheme === 'light' ? 6.69 : 7.47, 1)`; the title says "6.69 light, 7.47 dark" | 5.85 in light and 8.98 in dark, in the assertion and in the title. The floor `toBeGreaterThan(4.5)` stays. |
| `src/components/nph-togglebutton/nph-togglebutton.test.ts:1193` (comment at line 1181) | `['light 1.26', 'dark 1.54']`; the comment says "1.26:1 in light and 1.54:1 in dark" | `['light 1.26', 'dark 1.39']`, and the comment says 1.39:1 in dark. The known limit stays: the checked background is still under 3:1. |
| `fichas/nph-tooltip.md` (lines 129 and 267), `src/shared/metadata/nph-tooltip.json:123`, `.storybook/i18n/en.json`, `es.json` and `pt-BR.json` (line 1748) | "6.69:1 in light and 7.47:1 in dark" | 5.85:1 in light and 8.98:1 in dark, so the spec, the metadata and the Docs page say what the test measures. The metadata is generated again from the spec. |
| `fichas/nph-togglebutton.md` (lines 190 and 323), `src/shared/metadata/nph-togglebutton.json:204`, `.storybook/i18n/en.json`, `es.json` and `pt-BR.json` (line 2169) | the dark ratio of the checked background, 1.54 | 1.39 in dark; light stays 1.26. |

Why the numbers moved: on 2026-11-23 the gray of the semantic tokens moved from `core/neutral` and `core/surface/300`–`950` to `core/slate` (commit `f9196052`). The tooltip balloon and the page background in dark mode now resolve to slate tones, so the measured ratios changed. The new ratios come from the full suite run on `v/5.0.0` with the slate tokens. Both still pass the floor each test guards: 4.5:1 for the tooltip text; the togglebutton test pins a known limit, not a floor.

On 2026-11-24 `core/neutral` and `core/surface/300`–`950` were removed from `src/tokens/source/core.tokens.json`; no semantic token pointed to them. These two tests do not read those primitives, so the removal does not change the numbers above.

## Related, for the same pass
These places still name primitives that no longer exist. Each takes the current alias of `src/tokens/source/semantic.tokens.json`:
- `docs/tokens.md`, `docs/tokens.pt-BR.md` and `docs/tokens.es.md`: one example table shows `color/destructive-foreground` dark as `{core.neutral.950}` and `color/secondary-hover` as `{core.neutral.200}` / `{core.surface.700}`.
- `docs/operacao/tarefas/DSA-114.md`, section "What changed in the tokens" and its contrast table: written before the slate swap, they put `color/marker` on `core/neutral/400` (`#8f8f8f`) in light and `core/surface/400` (`#6f7782`) in dark. Today `color/marker` is `core/slate/400` (`#6f7d91`) in both schemes. The test, the spec and the metadata of DSA-114 take the figures of the current token, measured again. The gate and the decision references of DSA-114 stay as they are: they record what was decided.
- Test titles that only name the old primitives: `src/components/nph-button/nph-button.test.ts:423` ("surface/300 and surface/400") and `src/components/nph-table/nph-table.test.ts:1742` ("core/surface/800"). The assertions read semantic tokens and pass; only the words change.
- `scripts/test-invariance.mjs:67` uses `{core.surface.900}` in a synthetic example. It passes, because the proof builds its own copy; `{core.slate.900}` keeps it pointing at a real token.

## How it is proved
**`review-and-merge`** passes when `npx vitest run src/components/nph-tooltip src/components/nph-togglebutton` shows the two tests above green, the spec, the metadata and the three dictionaries carry the same figures as the tests, the proof commands in `docs/operacao/component-handoff.md` exit 0, and the change is merged into `v/5.0.0`.

## What this task does not do
It does not change a token, a component or a story. It does not touch the contrast of `status/on-solid` over `status/help` in dark mode (4.45:1, which turns the Emphasis and Actions stories of `nph-notification` red in axe): that choice is visual, it is in a Figma preview, and Indiane decides it there; a token change, if any, comes in its own push. It does not fix the other red tests that were already on `v/5.0.0` before the slate tokens.
