# DSA-117 — nph-separator takes separator/border (lighter divider)

## Goal
The divider reads lighter and has the same weight in light and dark mode. Today it uses
`color/border` directly: 1.72:1 on the page background in light, but 4.09:1 in dark, much
stronger than the light one. It moves to its own token, `separator/border`, which points to
`color/border-subtle`, the same color that the dividers of card, accordion, dropdown and
date-picker already use.

## What changed in the tokens (on v/5.0.0 in the same push as this task)
| Token | Points to | Light | Dark |
|---|---|---|---|
| `timeline/connector-border-pending` (new) | `color/border` | `core/slate/200` `#bfc6d1`, as today | `core/slate/400` `#6f7d91`, as today |
| `separator/border` (new) | `color/border-subtle` | `core/surface/200` `#d6dfeb`, 1.34:1 on `color/background` | `core/alpha/white-15`, 1.59:1 on `color/background` and 1.61:1 on `color/card` |

The CSS variable is `--nph-separator-border`. In Figma, the master `nph-separator`
(both variants) has its line bound to `separator/border`, and the documentation page of the
component names `separator/border` wherever it named `color/border`.

## What changes in the code
| File and line | Today | After this task |
|---|---|---|
| `src/components/nph-separator/nph-separator.css:21` | `background-color: var(--nph-color-border);` | `background-color: var(--nph-separator-border);` |
| `src/components/nph-separator/nph-separator.css:6` and `src/components/nph-separator/nph-separator.ts:7` (comments) | "the color is `color/border`" | "the color is `separator/border`" |
| `src/components/nph-separator/nph-separator.test.ts:72`, `:75` and `:110` | the test title, the probe and the set of consumed properties name `color/border` and `--nph-color-border` | `separator/border` and `--nph-separator-border` |
| `fichas/nph-separator.md` lines 34, 37, 41, 52, 69, 111, 116, 129, 149 and 181 | `color/border` | `separator/border`. The rule stays the same in meaning: the color is always `separator/border`, so a different color would turn the divider into a state signal. |
| `src/shared/metadata/nph-separator.json` (lines 40, 45, 50, 63 and 90) | `color/border` | generated again from the spec |

The divider stays decorative and `aria-hidden`: WCAG 1.4.11 (Non-text Contrast) asks 3:1 only
of what identifies a component, so the lighter line needs no contrast floor. The field border
is still `color/input`, which meets 3:1.

## Pieces that recolor the separator from outside
Ten components set the color of their own `nph-separator` by redefining `--nph-color-border`
on it. Once the separator paints with `--nph-separator-border`, that override no longer
reaches the line, and each of them would fall to `color/border-subtle` without notice. Each
line moves to the new property, with the same value, so these dividers keep the look they have
today:

|---|---|---|
| `src/components/nph-card/nph-card.css:395` | `--nph-color-border: var(--nph-card-divider);` | `--nph-separator-border: var(--nph-card-divider);` |
| `src/components/nph-command/nph-command.css:56` | `--nph-color-border: var(--nph-command-divider);` | `--nph-separator-border: var(--nph-command-divider);` |
| `src/components/nph-context-menu/nph-context-menu.css:71` | `--nph-color-border: var(--nph-dropdown-separator);` | `--nph-separator-border: var(--nph-dropdown-separator);` |
| `src/components/nph-date-picker/nph-date-picker.css:123` | `--nph-color-border: var(--nph-date-picker-divider);` | `--nph-separator-border: var(--nph-date-picker-divider);` |

The tests that pin these overrides follow: `src/components/nph-sidebar/nph-sidebar.test.ts:2068`
lists `--nph-color-border` among the properties the sidebar defines; it becomes
`--nph-separator-border` (the list is sorted, so the new name moves to its sorted place). Any other test of these ten pieces that reads the separator color
through `--nph-color-border` changes the same way.

**`nph-timeline`, the pending item.** Every status but pending paints the connector with
`timeline/connector-border` (`nph-timeline.css:149`–`155`); the pending item writes nothing, so its
connector takes the separator default. To keep the pending connector as it is today, a new
token paints it: `timeline/connector-border-pending` (`--nph-timeline-connector-border-pending`),
which points to `color/border`, already on v/5.0.0 in the same push and bound in Figma on the
connector of the pending item. Add the rule
`[data-status='pending'] .connector { background-color: var(--nph-timeline-connector-border-pending); }`
next to the rule at `nph-timeline.css:149`–`155`. `nph-timeline.test.ts:826`
(pending connector) expects `--nph-color-border`; it can keep that value or read
`--nph-timeline-connector-border-pending`, which resolves to the same color. `nph-timeline.test.ts:836`
checks a loose `nph-separator` appended to the body: it now expects `--nph-separator-border`.
`nph-timeline.test.ts:1206`–`1207` ("consumes every one of the twenty-seven timeline/* tokens",
`toHaveLength(27)`) is red on v/5.0.0 from the token push on: the group now has 28 tokens. The
title says twenty-eight and the length is 28, and the test also finds
`--nph-timeline-connector-border-pending` consumed once the pending rule above is in.

**Dividers that get lighter, as decided.** The separators that nobody recolors take the new
default: the dividers between groups of `nph-toolbar` (`::slotted(nph-separator)`, which sets
only the height) and the group separator of the `nph-combobox` list
(`nph-combobox.list.css:100`), which `nph-multi-combobox` also shows, the bulk-action separator
of the `nph-data-table` demo (an `nph-toolbar` separator, `nph-data-table.demo.ts:165`), and the `.divider` separators of `nph-navigation-menu` (`nph-navigation-menu.ts:836`
and `:950`; its CSS at line 256 sets only `flex: none`). This is the intended
effect of the decision.

**Text that names the old property, for the same pass.** Each takes `separator/border` or
`--nph-separator-border`:
- comments that say the piece redefines `color/border` for its divider: `nph-card.css:393`,
  `nph-command.css:21`, `nph-date-picker.css:10`, `nph-dialog.css:14`,
  `nph-dropdown-menu.css:77`–`78`, `nph-popconfirm.css:14` and `nph-popover.css:13`; they now
  redefine `separator/border`;
- comments that say the pending timeline item leaves the separator as it is:
  `nph-timeline.css:14`–`16` and `:148`, `nph-timeline.ts:60`; they now name
  `timeline/connector-border-pending`; the title of the timeline test at
  `nph-timeline.test.ts:824`;
- specs: `fichas/nph-command.md:424` and `fichas/nph-dialog.md:414` (each redefines only
  `separator/border` on its lines), `fichas/nph-timeline.md:280`, `:300`, `:459`–`460` and `:545` (the
  pending item paints `timeline/connector-border-pending`; the connector token list at line 300
  and the connector row of the token table gain it, and so does
  `src/shared/metadata/nph-timeline.json:267` when generated again) and `fichas/nph-accordion.md:529` (the separator line is
  `separator/border`, not `color/border`), with their metadata generated again.

The arrow divider and the shortcuts footer of `nph-combobox` keep `color/border`: they are
borders drawn by the combobox, not `nph-separator`, so their comments and spec stay.

**`DSA-105` (nph-rich-text-editor).** Its "Divider" item says the editor overrides
`--nph-color-border` on its separator. After this task, that override must write
`--nph-separator-border`, with the same value `rich-text-editor/divider`.

## How it is proved
**`review-and-merge`** passes when `npx vitest run src/components/nph-separator` and the tests
of the ten pieces above and of `nph-timeline` are green, the ten overrides write
`--nph-separator-border`, the spec, the metadata and the code comments name `separator/border`, the proof commands in
`docs/operacao/component-handoff.md` exit 0, and the change is merged into `v/5.0.0`.

## What this task does not do
It does not change `color/border` or `color/border-subtle`. It does not change the look of the
ten pieces above, nor of the `nph-timeline` connectors: they keep their colors through the
moved override. The arrow divider of `nph-select`, `nph-combobox` and `nph-tree-select` is
drawn by those pieces, not by `nph-separator`, and keeps `color/border`.
