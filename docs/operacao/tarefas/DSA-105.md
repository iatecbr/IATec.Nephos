# DSA-105 — nph-rich-text-editor, a form field with simple formatting

## Goal
The `nph-rich-text-editor` in `src/components/nph-rich-text-editor/`, with CSS, tests, stories and the spec `fichas/nph-rich-text-editor.md`, in the contract accepted in Figma: a multi-line form field for text with simple formatting, inside the `nph-field` as the `nph-textarea`, with the formatting toolbar at the top of the box. Toolbar: undo and redo, block style (Paragraph, Heading 1, 2, 3), bold, italic, underline, strike-through, bulleted and numbered list, quote, link and clear formatting; in a narrow box, history, link and More. Optional footer with the counter and the actions. States: default, hover, focus, error, error focus, disabled and read only.

## Where the contract is
In the evidence of the `figma-docs-accepted` gate: `docs/operacao/evidencias/DSA-105/figma-docs-accepted-2026-11-22.md`. It carries the Figma documentation converted to text, with the 31 tokens, the anatomy part by part (with the token and the text style of each layer), the measured contrast, the default behavior, the combined states, the inherited decisions, the icon rules, the limits, what the editor asks of other pieces and the decisions answered. There is no need to open Figma.

## Specification to follow closely
- **Parts and tokens**: as the anatomy of the evidence. The box, the divider, the text area, the content and the footer bind their `rich-text-editor/*` token, never the semantic it points to. Pieces by instance keep their own tokens.
- **Box**: `rich-text-editor/width` by default, stretching inside the `nph-field`; 1 px border `rich-text-editor/border-width` in `rich-text-editor/border` (hover `border-hover`, error `border-error`, focus `focus-border`), corners `rich-text-editor/radius`, background `rich-text-editor/background` (`background-disabled` when disabled). From the top: toolbar, divider, body.
- **Toolbar**: the `nph-toolbar`, compact, with its slots (P104, item 2), inside the box outline with no outline of its own, its top corners in `rich-text-editor/radius`. The host points the toolbar CSS variables, as P104, item 4. Groups in order with a vertical `nph-separator` between each two: history, block style, formatting, lists, quote, link, clear formatting. Icon-only buttons are 28 × 28; the block style trigger is an `nph-button` secondary ghost compact with text (the current style) and `chevron-down`.
- **Wide and narrow toolbar**: wide when the box has room for it (577 px inside the box with the trigger on Paragraph); otherwise narrow: history, link and More, with the other groups in More, in the order of the wide toolbar, the block style trigger going whole (item 3, the exception recorded in DSA-106), and Clear formatting last, after a separator (item 4). Two states only: no toolbar in between is drawn. How More is built today is D-1.
- **Divider**: a horizontal `nph-separator` below the toolbar, `rich-text-editor/divider-width`, in `rich-text-editor/divider`: the editor overrides `--nph-color-border` only on this separator, the path of the `nph-dialog` and the `nph-command` (DSA-80). The group dividers in the toolbar keep `color/border`.
- **Text area**: sides `rich-text-editor/content-padding-x`, top and bottom `rich-text-editor/content-padding-y`; minimum height `rich-text-editor/content-min-height`, maximum `rich-text-editor/content-max-height`, then the text scrolls inside and the toolbar stays in view. Placeholder `text/body-md` in `rich-text-editor/placeholder-foreground`, gone when the person types.
- **Content**: paragraph `text/body-md`; Heading 1, 2, 3 in `text/heading-md`, `text/heading-sm`, `text/heading-xs`; all in `rich-text-editor/foreground`; `rich-text-editor/block-gap` between blocks; lists indented `rich-text-editor/list-indent`, the marker outside the text; quote with a start bar `rich-text-editor/quote-border-width` in `rich-text-editor/quote-border` and the text `rich-text-editor/quote-padding-start` after it; link underlined in `rich-text-editor/link-foreground`.
- **Footer** (optional, inside the box): `rich-text-editor/footer-gap` below the area, counter at the start (`text/caption`, `rich-text-editor/counter-foreground`), actions at the end with `rich-text-editor/footer-actions-gap` between them, `rich-text-editor/content-padding-y` to the bottom border. The consumer writes the counter text; the counter counts the text, not the markup. Not drawn in read only.
- **Focus**: in the text area, the box shows `rich-text-editor/focus-border` and the halo `rich-text-editor/focus-halo` (`focus-halo-error` in error focus), `rich-text-editor/focus-halo-width`, corners `rich-text-editor/focus-halo-radius`, outside the box. Toolbar buttons show their own focus.
- **Toolbar buttons**: undo, redo, link, clear formatting and More are the `nph-button` icon only, secondary ghost compact square, with no `aria-pressed`; bold, italic, underline, strike-through, the two lists and quote are the `nph-togglebutton` icon only, compact, 28 × 28 (see "What it asks of other pieces"), with `aria-pressed`. Undo and redo are disabled with no history, and the arrow keys skip them. Each icon-only button has its name and an `nph-tooltip` with the name and the shortcut ("Bold · Ctrl+B"); a disabled button has no tooltip.
- **Block style menu**: an `nph-dropdown-menu` with Paragraph and Heading 1 to 3, single choice, the current one checked; while open, the trigger keeps the open look (`button/secondary-solid-background-hover`) and `aria-expanded` (DSA-67 D-2).
- **Link editing**: an `nph-popover` below the link button, align center, no arrow, size md, with the visible title "Link" (`text/heading-sm` by the popover; it names the surface, item 5), the `nph-field` "Link address" with the `nph-input`, then "Remove link" (secondary ghost compact, only when there is a link already) and "Apply". Ctrl or Cmd + K opens it.
- **Keyboard and roles**: the text area is role `textbox` with `aria-multiline`, named by the `nph-field` label, help and error in `aria-describedby`. The toolbar is role `toolbar`, named, with `aria-controls` to the area; it is one Tab stop, Right and Left move with wrap, Home and End; Tab leaves the editor (no trap); Alt+F10 goes from the area to the toolbar. Shortcuts: Ctrl or Cmd + B, I, U; Ctrl or Cmd + Z and Ctrl or Cmd + Shift + Z; Ctrl or Cmd + K. The full table is in the evidence.
- **Ctrl or Cmd + K and the `nph-command`** (item 13): with the focus in the editor, the editor handles the key and calls `preventDefault`; the palette ignores a key event already `defaultPrevented`, so the link opens and the palette does not.
- **Focus when the link closes** (item 12): opened by the link button, Esc, Remove link and Apply give the focus back to the button (the popover rule); opened by Ctrl or Cmd + K in the area, they give it back to the text area, at the cursor or the selection. A click outside closes without applying and leaves the focus where the person clicked.
- **States**: disabled fades the whole box with `rich-text-editor/disabled-opacity`, the toolbar and the footer actions included, and takes no focus; read only removes the toolbar and the divider, keeps the text readable and selectable, with no hover, and the area focus follows the `nph-textarea` in read only (DSA-38 D-2). Disabled wins over read only, read only wins over error; error + disabled: disabled. Checked + disabled keeps the checked background under the opacity.
- **Images**: none; inserting an image is out of the v1.

## What it asks of other pieces
- **`nph-togglebutton`**: an opt-in square form of the compact icon only, 28 × 28, used by the editor (Pend. 2 asks for the square; the opt-in is how this task keeps the other consumers as they are); today the sheet says the icon-only piece hugs its icon and is never square (50 × 28), and in Figma the master `2962:71772` measures 48 × 28 while the editor resizes its instances. The default icon only keeps its width for every other consumer, such as the `nph-toggle-group`. This task adds the opt-in (for example a shape attribute) to the `nph-togglebutton`, with its sheet.
- **`nph-dropdown-menu`**: no nested menu today. D-1.
- **`nph-icon`**: six icons enter the core in DSA-108 (blocker B1).
- **`nph-toolbar`, `nph-popover`, `nph-separator`, `nph-command`, `nph-textarea`**: unchanged here (the evidence says how the editor uses each).

## Open points for the code
- Event, aria, slot, property and console warning, following the APG and the Custom Elements Manifest.
- **Editing library**: the decision map asks the code owner for the technical validation of the editing library; no choice is made here. Read on 2026-11-22: Lexical documents an open shadow root "out of the box" and reads the selection with `Selection.getComposedRanges` (https://lexical.dev/docs/concepts/shadow-dom ); for ProseMirror (Tiptap) and Quill only forum reports were seen, of selection problems in Safari and Firefox inside a shadow root (https://discuss.prosemirror.net/t/prosemirror-inside-a-shadowroot/2387 ). Recommended: test the selection in Safari before choosing.
- **Value and form**: recommended, the value as clean HTML with only the allowed marks (`p`, `h1` to `h3`, `strong`, `em`, `u`, `s`, `ul`, `ol`, `li`, `blockquote`, `a[href]`, `br`), given to the form by `ElementInternals.setFormValue`, as the form-associated `nph-textarea`; the Mantine Tiptap example keeps HTML (https://mantine.dev/x/tiptap/ ). HTML a person writes in a WYSIWYG editor is sanitized: OWASP says "HTML Sanitization should be used" there and recommends DOMPurify (https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html ). The spec says where the editor sanitizes (on paste, on the value); the consuming server sanitizes too (no source read for the server side). Pasting keeps only the allowed marks and drops color, font, table, image and inline style (by analogy with the schema of ProseMirror and Lexical). The spec names the value format.
- **Link address**: recommended, only `https:`, `http:` and `mailto:`; another protocol (`javascript:`, `data:`) shows an error in the field "Link address"; an address with no protocol gets `https://`; the link opens in a new tab with `rel="noopener noreferrer"`. CKEditor 5 turns an unknown protocol into `#` and warns against unsafe protocols (https://ckeditor.com/docs/ckeditor5/latest/features/link.html ); Tiptap opens in a new tab by default with `noopener noreferrer nofollow` (https://tiptap.dev/docs/editor/extensions/marks/link ). In editing, a click on a link places the cursor and does not navigate; in read only, the link opens.
- **Counter and limit**: as the `nph-textarea`, the consumer writes the counter text and the editor does not stop typing at a limit; the editor gives the consumer the length of the visible text, without markup (recommended: by grapheme, with `Intl.Segmenter`, as the Tiptap example: https://tiptap.dev/docs/editor/extensions/functionality/character-count ). Passing the limit is said by the `nph-field` error, the soft limit of the CKEditor example (https://ckeditor.com/docs/ckeditor5/latest/features/word-count.html ).
- **Enter**: Enter makes a new paragraph or list item and never submits the form; Shift+Enter breaks the line in the same block (Tiptap: https://tiptap.dev/docs/editor/core-concepts/keyboard-shortcuts ). Markdown shortcuts ("- ", "1. ", "> ") stay off: they are out of the v1 (matrix). Shortcuts for strike-through, lists and quote with no drawing (Tiptap: Ctrl or Cmd + Shift + S, 8, 7, B) are optional; when they exist, the tooltip writes them.
- **Wide or narrow**: by the box width, not the screen. Recommended: a container query on the host (`container-type: inline-size`); a ResizeObserver only if More must be built by script. Neither editor read says how it measures (TinyMCE: "small editor frames", https://www.tiny.cloud/docs/tinymce/latest/toolbar-configuration-options/ ).
- **Mixed selection**: a selection that is partly bold. The look stays unchecked (no system read draws a mixed look); whether the button announces `aria-pressed="mixed"` is named by the spec.
- **Link with no selection, and where Ctrl or Cmd + K holds**: with the cursor collapsed, Apply inserts new text wrapped in the link at the cursor; CKEditor 5: "When the selection is collapsed, it creates new text wrapped in a link" (https://ckeditor.com/docs/ckeditor5/latest/features/link.html ). Recommended: that text is the address itself (by analogy; the page does not say which text). Ctrl or Cmd + K holds with the focus in the text area; recommended, also with the focus on a toolbar button, acting as the link button (the focus then goes back to the link button), by analogy with item 13 ("with the focus in the editor"). The spec names both.
- **Empty and required**: recommended, by analogy with an empty native field: the editor is empty when it has no visible text (only empty paragraphs or spaces), and then the value sent is an empty string, not an empty paragraph. With `required`, the editor reports `valueMissing` through `ElementInternals.setValidity`, "true if the element has a required attribute, but no value" (https://developer.mozilla.org/en-US/docs/Web/API/ElementInternals/setValidity ), as the `nph-textarea` reports its validity through its internals today; the `nph-field` shows the message (required example c). The spec names it.
- **Texts and shortcuts**: the button names, "Link", "Link address", "Remove link", "Apply", the invalid address message and the toolbar name come from translation keys, as in the other pieces; the tooltip writes the shortcut of the platform (the documentation example writes "Bold · Ctrl+B"; on macOS, the Command key). The spec names them.
- **Disabled opacity inside the box**: the actions and buttons inside the disabled box keep their own opacity too, about 25% on screen, as the `nph-textarea` today (DSA-38 D-5).

## Why it is blocked
The `rich-text-editor/*` tokens and the semantics `layout/multiline-min-height` and `layout/multiline-max-height` came with this task and are on `v/5.0.0`: 28 alias tokens of the same function and 3 straight to the core by decision (`rich-text-editor/content-padding-y`, `rich-text-editor/quote-padding-start`, `rich-text-editor/list-indent`; the evidence says why), with no new value in the core. Every piece it uses is done: `nph-icon` (DSA-03), `nph-separator` (DSA-10), `nph-button` (DSA-13 and later), `nph-input` (DSA-16), `nph-togglebutton` (DSA-22), `nph-field` (DSA-28), `nph-textarea` (DSA-38), `nph-tooltip` (DSA-42, DSA-48), `nph-dropdown-menu` (DSA-45), `nph-toolbar` (DSA-55), `nph-popover` (DSA-67), `nph-command` (DSA-80). It waits for DSA-108, the six icons (B1), and for the answer to D-1, the More menu (B2).
