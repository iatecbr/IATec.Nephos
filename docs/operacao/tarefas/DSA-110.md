# DSA-110 — `nph-button`: junction corners, focus halo hook and the tooltip of a menu trigger

## Goal
The `nph-split-button` (DSA-109) is built with two `nph-button`s, the main part and the arrow (icon only). Three things it needs are not in the `nph-button` today. This task adds them, each unset by default, so every other button draws and behaves exactly as before.

## Where the decision is
In the evidence of the `foundation-decision` gate: `docs/operacao/evidencias/DSA-110/foundation-decision-2026-11-23.md`, and in the DSA-109 evidence ("What the split asks of other pieces"). There is no need to open Figma.

## What changes
Pend. 2, 7, 12 and 13 of the split were accepted with the proposals on 2026-11-22 and kept with no veto on 2026-11-23 (see the evidence).

1. **Corners at a junction** (Pend. 2 and 7, accepted with the proposals). Today the button draws `radius/control` on its four corners, its focus border `focus/border-radius-control` and its halo `focus/radius-control-with-border`, with no way for a host to change one side. The split needs, on the side of the junction only, the button corners in `split-button/inner-radius` (4), the focus border corners in `split-button/focus-border-inner-radius` (5) and the halo corners in `split-button/focus-halo-inner-radius` (9): the end corners of the main part and the start corners of the arrow, by logical side, so right to left mirrors. Recommended: public custom properties per logical side, as the existing `--nph-button-focus-border` (DSA-72, P116), set by the host on that button only; the names and whether one hook covers the three layers are the code owner's choice.
2. **Focus halo color** (Pend. 12, accepted with the proposals). The one public focus hook is `--nph-button-focus-border` (the border only); the halo has no hook (P116, item 8). The split uses `focus/border` and `focus/halo` on both parts in every type, the danger part included, where the button alone uses `focus/halo-danger`. Recommended: a sibling hook for the halo color, with the same rule as the border hook: set on the button, never on a host that holds other buttons, because a custom property inherits.
3. **Tooltip of an icon-only button that opens a menu** (Pend. 13, accepted with the proposals). Today the tooltip opens on keyboard focus at once (`fichas/nph-tooltip.md`), and nothing hides it while a menu is open. New rule: on an icon-only button whose host carries `aria-haspopup="menu"` and `aria-expanded` true, the tooltip stays hidden while the menu is open, and does not reopen when the focus comes back to the button as the menu closes; it comes back only on a new hover or a new keyboard focus. It holds for every icon-only button that opens a menu, in any screen. Precedent: Primer hides the tooltip of its icon button while its menu is open (https://raw.githubusercontent.com/primer/react/main/packages/react/src/Button/IconButton.tsx ).

The spec, the metadata and `docs/decisoes-tecnicas.md` record the three changes where the focus, the corners and the tooltip of the icon-only button are written today.

## How it is proved
**`foundation-decision`** — passed. **`review-and-merge`** — a test per change (the hooks unset draw as before; set, they change only the named corners or color; the tooltip stays hidden while the menu is open and does not reopen on the focus return), the proof commands in `docs/operacao/component-handoff.md` exit 0, and the work is merged into `v/5.0.0`.

## What this task does not do
It does not create a token or change a token value. It does not build the split (DSA-109). It does not change the focus of the primary `nph-button` alone in dark, a foundation finding outside this task.
