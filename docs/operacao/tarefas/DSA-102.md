# DSA-102 — nph-tree-table, a data table with a hierarchy

## Goal
The `nph-tree-table` in `src/components/nph-tree-table/`, with CSS, tests, stories and the spec `fichas/nph-tree-table.md`, in the contract accepted in Figma: a data table whose rows have a parent and child hierarchy and the same columns at every level. The first column carries the tree (indent per level, chevron, text), as the `nph-table` tree cell; the rest is the table of the `nph-data-table`: caption, toolbar, sortable header, selection box, footer with pagination, loading and empty by search. A branch can load its children on demand; when the load fails, the branch error row takes their place. States: default, loading, empty by search; sizes default and large.

## Where the contract is
In the evidence of the `figma-docs-accepted` gate: `docs/operacao/evidencias/DSA-102/figma-docs-accepted-2026-11-22.md`. It carries the Figma documentation converted to text, with the 20 tokens of the gate (the floor token, `tree-table/tree-column-min-width`, is in D-2 below), the anatomy part by part (with the token and the text style of each layer), the measured contrast, the default behavior, the combined states, the inherited decisions, the icon and image rules, the limits, what the tree table asks of other pieces and the decisions answered. There is no need to open Figma.

## Specification to follow closely
- **Parts and tokens**: as the anatomy of the evidence. The table parts bind the `nph-data-table` and `nph-table` tokens the evidence names; the branch error row and the row focus bind their `tree-table/*` token, never the semantic it points to.
- **Table**: caption, toolbar, header, body and footer stacked with `data-table/stack-gap`; caption, toolbar, header, selection column, selected row, pagination, loading and empty by search as the `nph-data-table` (DSA-58), sizes default and large as there (large: `table/container-padding` on the cell sides and a selection column 8 px wider; the row with actions measures 53 px in both).
- **Tree column**: the first column, the `nph-table` tree cell: `table/expand-indent` plus `table/cell-gap` per level below the first (36 px per level), the chevron (`nph-button` icon only, ghost, compact, `chevron-right` closed, `chevron-down` open), the empty chevron space on a leaf, and the text. Up to three levels (item 3); a row below the third level is left out, as the `nph-table` does, and warns in the console.
- **Long text** (item 10): the tree cell text is cut to one line with an ellipsis, the whole text in the `nph-tooltip` on hover and on focus, closing with Esc, as the `truncated` cell of the `nph-table`. The `nph-table` tree opens the hover tooltip only in the row that is the Tab stop (its known limit, P101); the tree table follows the accepted documentation (hover and focus) the way the `nph-tree` does it (`fichas/nph-tree.md`, known limit (c)): while the pointer is over a cut text, its row takes the Tab stop, and gives it back when the pointer goes to another row, leaves the table or the person presses Tab. The `nph-table` keeps its limit.
- **Row background** (item 10): rest `table/background` (the data table row), hover `table/row-hover-background` on the whole row, selected `data-table/row-selected-background` with the 2 px bar `data-table/row-selected-indicator` (`data-table/row-selected-indicator-width`) at the start, above the focus. The tree cell has no background of its own: it takes the same background as the other cells of the row in every state (rest, hover, selected). Hover only paints; it does not move the focus.
- **Row focus** (accepted proposal, border and halo; only in the tree table): with the keyboard, the focused row shows the halo `tree-table/focus-halo` (`tree-table/focus-halo-width`, corners `tree-table/focus-halo-radius`) at the edge and the border `tree-table/focus-border` (`tree-table/focus-border-width`, corners `tree-table/focus-border-radius`) inset 4 px, both inside the row and stopping 1 px above the base divider; the selected bar stays above the focus. This replaces, in the tree table only, the 2 px ring `table/focus-ring-width` that the `nph-table` tree draws today (P101, item 3); the `nph-table` keeps its ring. A focused cell keeps the ring of the `nph-table`; the chevron, the box and the buttons keep the focus of their own piece.
- **Selection**: the box in a column of its own, at the start, with no indent, only by the box, as in the `nph-data-table`. Checking the parent checks the loaded children; with only part of them checked, the parent box is indeterminate (`minus`, item 10). The header box checks the drawn rows, open children included (DSA-58 D-4, in part); the bulk bar as in the `nph-data-table`. A click on the rest of the row neither checks the box nor opens the branch.
- **Loading branch** (accepted proposal, the loading chevron): the branch opens, the chevron becomes the `nph-button` loading state, with no skeleton row, and the row takes `aria-busy="true"`; opened by the keyboard, the focus stays on the row. The children arrive under the parent, or the error row in their place. The first load of the whole table is the `nph-data-table` loading state; a failed first load has no row in the contract, as in the `nph-data-table` (no domain error state) and the `nph-tree` (known limit (h)): the page shows its own message.
- **Branch error row** (accepted proposal, the error row at the children's level): a whole row at the children's level, background `tree-table/row-background` (hover `tree-table/row-background-hover`), divider at the base `tree-table/border` (`tree-table/border-width`), top and bottom padding `tree-table/row-padding-block` with `tree-table/row-height` as a floor. Inside, from the start: the selection space (when the table has selection), the error cell (sides `tree-table/cell-padding-inline`, gap `tree-table/cell-gap`) with one `tree-table/indent` per level below the first plus the chevron space (`tree-table/indent`), then the error block (gap `tree-table/error-gap`): `triangle-exclamation` light (`tree-table/error-icon-size`, `tree-table/error-icon-foreground`), the message in `text/body-md` and the action "Try again" in `text/label-md`, both in `tree-table/error-foreground` (`tree-table/error-foreground-hover` in hover). The icon sits under the text of the sibling rows. The whole row is the target; Enter and a click try again. It takes hover and the row focus, and it is not selectable. The name read is the message and the action together.
- **Try again**: the error row leaves and the parent row goes back to the loading state drawn above (loading chevron, `aria-busy="true"` on the parent row) until the answer arrives: the children under the parent, or the error row again. When the error row held the focus, the focus goes to the parent row, the nearest branch still drawn, as the `nph-tree` does (`fichas/nph-tree.md`, focus: "When the item that holds the focus leaves, the focus goes to the nearest branch that is still drawn"). Figma draws no loading error row; this uses only the drawn states.
- **Error row measures** (items 4 and 5): the selection space takes the real width of the selection column of the table in both sizes, with no token of its own. The row height is the data row height of the same table: that rule wins. `tree-table/row-padding-block` (12 above and below) is what reproduces the 53 px rows of the Figma table with actions; in a table with lower rows (40, or 44 in large, with no actions column) the height rule wins over the padding, and `tree-table/row-height` stays only as a floor.
- **Keyboard and roles**: a treegrid, as the `nph-table` tree (P101): rows with `aria-level`, `aria-posinset`, `aria-setsize`, `aria-expanded` on a row that opens. One body row is the Tab stop; Tab goes on to the box, the chevron, the buttons and the truncated text of that row, then leaves the table. On a row: Down and Up, Right (open or first cell), Left (close or parent), Home and End, Enter (open and close; try again on the error row). On a cell: the `nph-table` cell keys. Space and Enter on the box check it. A click on the rest of the row does not open the branch. The full table is in the evidence.
- **Sorting, search and pagination**: the sort works inside each level, with the children under the parent; the search shows the matching rows and their parents; the pagination counts only level 1 rows, and the children stay on the page of the parent.
- **Images**: none of its own; the `nph-empty` illustration in empty by search, by instance.

## Open points for the code
- Event, aria, slot, property and console warning, following the APG and the Custom Elements Manifest.
- **API**: today the `nph-data-table` leaves out a row with children and lists "a tree of records" under "do not create without a decision", and the `nph-table` tree has no selection (P101). This task is that decision. How the `nph-tree-table` is built (a new element over the `nph-table` tree with the data table parts, or a tree mode the data table gains) and how a row declares its children, its loading and its load error (to show the error row and to ask for the load again) stay with the code; the look and the tokens do not change. The spec names them.
- **Cascading selection, the full rule**: the accepted rule is "checking the parent checks the loaded children; with only part of them checked, the parent is partial". Not drawn, and named by the spec, with the look unchanged: (a) all the children checked one by one: whether the parent becomes checked; (b) unchecking the parent unchecks its loaded children; (c) what the selection reports, and what the bulk bar counts (parents, children or both), for a parent whose children are not loaded yet; (d) the children that load later under a checked parent. The `nph-tree` cascade (`fichas/nph-tree.md`, multiple selection) is the nearest precedent.
- **The tree cell background**: in code the cell sits inside the row; the `nph-table` hover paints each cell of the row (`nph-table.css`), so the tree cell takes it as the other cells do, with no background rule of its own that would win over the hover or the selected background.
- **Partial box on a row**: the `nph-checkbox` has the indeterminate state, but the data table uses it only on the header box today; the tree table puts it on the parent row box. The data table itself does not change.
- **Error row roles**: the error row sits in the treegrid at the children's level; its `aria-level`, and whether it counts in `aria-setsize` and `aria-posinset` of the siblings, follow the `nph-tree` error row; the spec names them. Closing and opening a failed branch shows the error row again; only Try again asks for the load, as the `nph-tree`.
- **Error row text**: the message ("Couldn't load.", as the `nph-tree` error row) and the action ("Try again") and their translation keys; the spec names them, as `fichas/nph-tree.md` does.
- **Search, sort and pagination over a hierarchy**: the rules are accepted (sort inside each level; search with the parents; pagination by level 1). Not drawn: whether a match under a closed parent shows that parent open. Where they run (client or server, with on-demand children) stays with the code.
- **Narrow window**: the table scrolls horizontally in its own scroll area, as the `nph-table` does; the tree column is not fixed (out of the v1).
- **Empty branch** (D-1, answered on 2026-11-22): a branch that loads and comes back with no children becomes a leaf: the chevron leaves, its space stays, and the row stops carrying `aria-expanded`.
- **Tree column width** (D-2, answered on 2026-11-22): the page gives the width of the tree column, as any column, and the component keeps a floor of 240 px. The floor is the token `tree-table/tree-column-min-width` (240 px), on `v/5.0.0`: the tree column takes it as its minimum width and does not write 240 px by hand. It points straight to the new primitive `core/layout-width/tree-column` by decision, since `layout/separator-width` and `popover/width-sm` are 240 with another function. The cut text needs that width, as the `truncated` cell of the `nph-table`.

## Why it is ready
The `tree-table/*` tokens came with this task and are on `v/5.0.0`: 16 alias tokens of the same function (two of them on the `table/*` row hover, by decision of the design owner) and 4 straight to the core by decision (`tree-table/indent`, `tree-table/cell-padding-inline`, `tree-table/row-padding-block`, `tree-table/row-height`; the evidence says why). After D-2, `tree-table/tree-column-min-width` came with its own token commit, straight to the new primitive `core/layout-width/tree-column` (240) by decision, the one new value in the core for this task; no semantic changed value. D-1 and D-2 were answered on 2026-11-22. Every piece it uses is done: `nph-icon` (DSA-03), `nph-badge` (DSA-12), `nph-button` (DSA-13 and later), `nph-checkbox` (DSA-17), `nph-skeleton` (DSA-26), `nph-select` (DSA-29), `nph-empty` (DSA-40), `nph-tooltip` (DSA-48), `nph-table` (DSA-49), `nph-pagination` (DSA-54), `nph-toolbar` (DSA-55), the `nph-table` tree (DSA-56), `nph-data-table` (DSA-58).

## What this task does not do
The code does not create a token or change a token value. It does not change Figma. Item 10 of the approval also approved new variants on two Figma pieces of other components: the `nph-table` tree cell `2571:66335` gains the state axis (default, hover, stripe) and the cut to one line with the tooltip, and the `nph-data-table` selection `1371:68` gains the row place with the indeterminate box. The design side adds them in Figma, apart from this task; the code does not wait for them, and does here what the accepted composition draws (the rules above). It does not change the `nph-table` tree focus (the 2 px ring stays there) nor the `nph-data-table` behavior outside the tree table. It does not add a disabled row, expand and collapse all, a fixed tree column, a stripe or the other types out of the v1 (evidence, "Limits"). The foundation findings (the selected bar in `Gerencial` dark, the `table/*` divider, a row height semantic) go to a foundation task.
