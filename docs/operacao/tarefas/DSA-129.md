# DSA-129 — nph-input: text prefix and suffix

## Goal
A field for money, a measure or a user name shows a short text glued to the value, such as `R$` before
`1.250,00`, `kg` after `72` or `@` before a user name. The text is part of the nph-input itself, inside its
border and its focus ring. It is decoration: the unit is also in the label ("Value, in reais"), so a
screen reader does not need it. GOV.UK, USWDS, MUI, Primer, Atlassian and Ant Design all put this short
text inside the field; GOV.UK and USWDS hide it from screen readers with `aria-hidden`, and the Nephos follows
them.

This task is not part of the v1 cut.

## What changed in the tokens (on v/5.0.0 in the same push as this task)
- New `input/affix-foreground` → `color/muted-foreground` (the placeholder tone). Generated
  `--nph-input-affix-foreground`. Light 8.07:1 and dark 9.96:1 on the page background, as the placeholder.
- New `input/affix-gap` → `space/inline` (8). Generated `--nph-input-affix-gap`.
- No new value: both point to semantic tokens that already exist (T9).

## What Figma draws
Set `nph-input` `622:18359` (page `420:2`), in every size and state:

- New properties: `prefixo` (boolean, off by default) with `⮑ texto do prefixo` (text, default `R$`),
  and `sufixo` (boolean, off by default) with `⮑ texto do sufixo` (text, default `kg`).
- Inside the field, between the start icon and the clear target, one `conteúdo` row holds, in this order:
  prefix, placeholder, value, suffix. The row fills the free width and its gap is `input/affix-gap`.
  The value fills the rest, so the suffix sits at the end, next to the clear target when it shows.
- Prefix and suffix: one line, text style `text/body-md`, as the value, color `input/affix-foreground`. They keep their own width and do not wrap.
- The gap between the start icon and the row, and between the row and the clear target, stays
  `space/inline`, as today.
- Prefix and suffix stay visible with the placeholder (empty field) and with the value.
- Disabled: prefix and suffix follow the opacity of the whole field (0.5), as the value.
- Focus, error and hover: the border and the focus ring are the field's own; prefix and suffix do not change.
- Proof board with real instances in light and dark: `8516:97254` (draft page `988:6952`), next to the
  accepted preview `8475:36969`. It also shows the start icon with a prefix and the clear target, and a
  suffix with the placeholder.

## Default behavior

| Topic | What happens |
|---|---|
| Keyboard | Prefix and suffix are not focusable. Tab goes to the inner input, as today. |
| Pointer | Prefix and suffix are not interactive and have no action of their own. A click on them is a click on the field frame, so it moves the focus to the inner input, as a click on the frame does today. |
| Screen reader | Prefix and suffix carry `aria-hidden="true"`. The unit goes in the label or the hint, written by the product ("Value, in reais"). |
| Typed symbol | The field does not block or strip a symbol the person types (such as `R$`); validation is the product's (GOV.UK). |
| Long value | The value scrolls inside its own box and keeps its start alignment, as today; prefix and suffix stay in place and do not shrink. |
| Empty affix | A prefix or suffix text that is empty, or only spaces, draws no affix element. |
| Long affix | An affix is a short unit or symbol of a few characters (R$, kg, @), as in GOV.UK and USWDS; Figma draws no long affix. A longer text belongs in the label or the hint, not in the affix. |
| Content | The affix is plain text. A button or a select glued to the field is not an affix (see "What this task does not do"). |
| With start icon or clear target | Both can show with an affix; the order is icon, prefix, value, suffix, clear target. |

Event, aria, slot, property and console warning stay with the code (Elvys), following the APG and the Custom
Elements Manifest. By the current contract of the nph-input (no slot), prefix and suffix are two text
attributes, as `icon-start` and `icon-end` are; their names follow the existing names of the Nephos and the
spec names them.

## Combined states
Rule T11: the states combine as in the set. An affix does not add a state: hover, focus, error, error with
focus, disabled and focus with clear look the same with and without it.

## What changes in the code
- `src/components/nph-input/`: two optional texts, prefix and suffix, drawn before and after the inner
  input, inside the container. They read `--nph-input-affix-foreground`; the gap between the affix and the
  inner input is `--nph-input-affix-gap`. Without them, the field looks and behaves as today.
- The nph-input spec, stories (light and dark: prefix `R$`, suffix `kg`, prefix `@`, empty with
  placeholder, disabled, compact and large) and tests (aria-hidden on the affix; no affix element when the
  text is empty).

## How it is proved
- Stories in light and dark show the cases of the Figma proof board `8516:97254`.
- `npm test` for nph-input.

## What this task does not do
It does not create or change a token. It does not change Figma. It does not add an interactive addon (a
button or a select glued to the field): that is the `nph-input-group` case, not decided.
