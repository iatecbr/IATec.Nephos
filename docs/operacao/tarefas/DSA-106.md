# DSA-106 — `nph-toolbar` narrow bar: exception for a trigger whose text is a value

## Goal
The `nph-toolbar` spec says that on a narrow screen the consumer drops the text of the buttons first and then sends the actions at the back to More (DSA-55 D-5, open). In the `nph-rich-text-editor` (DSA-105) the block style trigger shows the style of the block where the cursor is ("Paragraph", "Heading 1"): its text is a value, not a caption, and cannot leave. The design owner decided that this trigger goes whole to More, with its group; in More it is the labeled group "Block style", a single choice with the current value checked (DSA-105 D-1, answered on 2026-11-23: More is one flat menu with labeled groups). The spec and the metadata gain that exception.

## Where the decision is
In the evidence of the `foundation-decision` gate: `docs/operacao/evidencias/DSA-106/foundation-decision-2026-11-22.md`. There is no need to open Figma.

## What changes
In `fichas/nph-toolbar.md` and `src/shared/metadata/nph-toolbar.json`, after the rule "The bar does not wrap and does not collapse by itself: on a narrow screen, the consumer drops the text of the buttons first, then sends the actions at the back to More (pending decision D-5)", in the business rules and in the narrative part of the spec where the same rule is written:

- New text, in the spec's own words: a button whose text is a value (the current choice of a menu, such as the block style of the `nph-rich-text-editor`) keeps its text: on a narrow screen it goes whole to More, as its labeled group with the current value checked, instead of becoming icon only. Precedent: `nph-rich-text-editor`, DSA-105.

D-5 of DSA-55 stays open (whether the bar collapses by itself); this exception does not answer it. Before closing, search the spec, the metadata and `docs/decisoes-tecnicas.md` (P104, item 7) for the narrow bar rule, and add a note that names DSA-106 where the rule is written; the old text stays as history in the evidence.
