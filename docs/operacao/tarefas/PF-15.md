# PF-15 — sombra e elevação no gerador, com PF-16 e PF-05

## Objetivo
Os 24 primitivos `core/shadow-*`, os 11 estilos de efeito, o movimento que faltava e o
laço do girador estão na branch padrão. Percebe-se que existe quando `npm run build:tokens`
na `v/3.0.0` emite a sombra e o CSS gerado a contém.

## IDs relacionados
**PF-16** — `core/duration/400` e `core/easing/linear`. **PF-05** — a duração de 800 ms
do laço do girador, que entrou como `core/duration/loop` e o sexto papel semântico
`motion/loop-duration` / `motion/loop-easing`.

As três viajaram no mesmo PR por decisão registrada da sequência. **Não têm tarefa
própria**: duplicar o ID criaria duas fontes para um trabalho só, que é o erro que esta
estrutura existe para impedir.

## Como se prova
**`pr-aberto`** — o **PR #19**, `feat(tokens): sombra, elevação e movimento — PF-15,
PF-16 e PF-05`, base `v/3.0.0`, head `feat/pf15-pf16-pf05-tokens`, 2 commits — `cdb4df5`
e `eec7542` — sobre `f6906d6`. **Passou:** a evidência está em
`docs/operacao/evidencias/PF-15/pr-aberto-2026-09-08.md`, com o comando e a saída
colados. Um merge de pull request não existe sem o pull request.

**`revisao-e-merge`** — o PR #19 foi mergeado na `v/3.0.0` no merge commit **`ec09459`**,
que é ancestral da ponta atual da branch padrão. **Passou:** evidência em

## O que esta tarefa não faz
Não implementa componente. Não reabre PF-16 nem PF-05, que estão fechadas como decisão e
execução. Não decide a duração da barra indeterminada do `nph-progress`, que continua sem
valor porque a peça foi adiada.
