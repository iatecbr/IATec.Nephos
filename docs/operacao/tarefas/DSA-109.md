# DSA-109 — nph-split-button, a dominant action with variations

## Goal
The `nph-split-button` in `src/components/nph-split-button/`, with CSS, tests, stories and the spec `fichas/nph-split-button.md`, in the contract accepted in Figma: a group of two parts, the main part (an `nph-button` with the label and an optional start icon) and the arrow (an `nph-button` icon only, square, `chevron-down`), 2 px apart. The main part runs the most common action with one click; the arrow opens an `nph-dropdown-menu` with up to five variations of that action. Type secondary (default), primary or danger; emphasis solid (default), outline, ghost or light (light only in primary; danger only in outline); size compact, default or large; state default, open, loading or disabled; and the main part alone or the arrow alone disabled.

## Where the contract is
In the evidence of the `figma-docs-accepted` gate: `docs/operacao/evidencias/DSA-109/figma-docs-accepted-2026-11-23.md`. It carries the Figma documentation converted to text, with the 6 tokens, the anatomy part by part (with the token of each layer), the focus ring, the default behavior, the combined states, the inherited decisions, the icon rules, the order of the parts, the limits, what the split asks of other pieces and the decisions answered. There is no need to open Figma.

## Specification to follow closely
- **Parts and tokens**: as the anatomy of the evidence. The group binds its `split-button/*` token, never the semantic it points to. Colors, size, padding and text come from the `nph-button` by instance and get no split token.
- **Shell**: horizontal, no background and no border, hugs both parts; `split-button/gap` (2 px) between the main part and the arrow; both parts centered vertically, with the same height (`control/height-*`).
- **Main part**: an `nph-button` with the same type, emphasis and size as the group, label and optional start icon, no end icon. Outer corners `radius/control`; the two corners at the junction (end side) `split-button/inner-radius`.
- **Arrow**: an `nph-button` icon only, shape square, the same type, emphasis and size; `chevron-down` light at rest and solid in hover-active; `chevron-up` solid while the menu is open (the open trigger look, P111 and P114). Icon size by size: `icon/size-sm`, `icon/size-md`, `icon/size-lg`. The two corners at the junction (start side) `split-button/inner-radius`; outer corners `radius/control`. Its label, the accessible name and the tooltip text, is built from the action, such as "More options for Save" (see "Open points").
- **Focus**: keyboard only, per part, one color in every type: the 1 px border in `split-button/focus-border` and the 4 px halo in `split-button/focus-halo`, the danger part included (the `nph-button` alone uses `focus/halo-danger`). Outer corners as the `nph-button` (`focus/border-radius-control`, `focus/radius-control-with-border`); junction corners `split-button/focus-border-inner-radius` (5) and `split-button/focus-halo-inner-radius` (9). The part with focus is painted on top of its neighbor, so the ring shows whole over the 2 px gap. The hooks come from DSA-110.
- **Menu**: an `nph-dropdown-menu`, 4 px below the group (`space/inline-tight`), aligned to the end edge of the group, turning up when it does not fit below (DSA-111 gives the end alignment). It writes `aria-haspopup="menu"` and `aria-expanded` on the arrow (P92).
- **Tooltip of the arrow**: the `nph-tooltip` of the icon-only button, 8 px above (`space/inline`), centered on the arrow (Pend. 20, option 1; the `nph-tooltip` already centers on the element, P77). Hidden while the menu is open; it does not reopen when the focus comes back to the arrow, only on a new hover or a new keyboard focus (DSA-110).
- **States**: open paints the arrow in hover-active with `chevron-up`; loading shows the `nph-button` spinner on the main part, which stays focusable with `aria-busy`, and disables the arrow; disabled fades the whole group with `state/disabled-opacity`; the main part alone or the arrow alone can be disabled, and the other part stays normal.
- **Keyboard and focus**: two Tab stops, the main part and the arrow. The arrow opens the menu with Enter, Space or Down Arrow (focus on the first item) and Up Arrow (focus on the last); Esc closes it and gives the focus back to the arrow. On the main part, Enter and Space run the action, and Down and Up Arrow do nothing (item 11). The full table, moment by moment, is in the evidence ("Default behavior").
- **Focus when a part becomes disabled** (item 12): when loading starts with the focus on the arrow, the focus goes to the main part; when the whole group becomes disabled with the focus on a part, that part keeps `aria-disabled` while it has the focus and leaves the Tab order when it loses it. The focus never falls on the body.
- **Click on the main part with the menu open** (item 13): it closes the menu and runs the action of the main part in the same click.
- **Right to left**: the code mirrors by the logical corners (start and end); the chevron does not mirror.
- **Images**: none.

## What it asks of other pieces
- **`nph-button`** (DSA-110, blocker B1): a hook for the junction corners (the button and its focus border and halo), a hook for the focus halo color (Pend. 12), and the tooltip of an icon-only button that opens a menu hidden while the menu is open (Pend. 13).
- **`nph-dropdown-menu`** (DSA-111, blocker B2): an end alignment, as the `align` of the `nph-popover` (item 9).
- **`nph-toolbar`** (DSA-112, after this task): each part of the split is an action of the bar (item 10). This task does not change the `nph-toolbar`.
- **`nph-tooltip`**, **`nph-icon`**: unchanged here.

## Open points for the code
- Event, aria, slot, property and console warning, following the APG and the Custom Elements Manifest.
- **Menu items**: recommended, the items are given to the split (a slot or a property, as the code owner chooses) and the split renders the `nph-dropdown-menu` with its arrow as the trigger: the menu finds its trigger by `for` in the same root (P92), and the arrow lives inside the split. Web Awesome places the dropdown inside the group ("Place a dropdown anywhere in the group to attach a menu of related actions", https://webawesome.com/docs/components/button-group ); Atlassian allows only two children in its split button (https://atlassian.design/components/button/split-button/code ).
- **Events**: recommended, an event of the group for the action of the main part, separate from the menu selection, because a native `click` also bubbles from the arrow; the menu selection keeps the `nph-item-select` of the `nph-dropdown-menu`. Fluent separates the props of the primary action button from those of the menu button (https://raw.githubusercontent.com/microsoft/fluentui/master/packages/react-components/react-button/library/src/components/SplitButton/SplitButton.types.ts ). The event names follow the Nephos pattern (no source read for the names).
- **Name of the arrow**: the `label` of the icon-only `nph-button` is its accessible name and the text of its tooltip, announced once (the `nph-button` spec). Recommended: built from the label of the main part ("More options for" + label), with a property that replaces the whole text, and the phrase from a translation key, as in the other pieces (no source read for the default phrase).
- **Group role**: recommended, `role="group"` on the shell, with an optional name. shadcn sets `role` `group` on its button group and recommends `aria-label` or `aria-labelledby` (https://ui.shadcn.com/docs/components/button-group ); Fluent does not use it (appendix, section H). A technical choice of the code.
- **Disable one part**: recommended, two properties next to the group `disabled`, one for the main part and one for the arrow; Fluent exposes the two buttons as separate slots (same `SplitButton.types.ts`). The names are the code owner's.
- **Focusable disabled**: Fluent has `disabledFocusable` next to `disabled` (same source), the same idea as item 12.
- **Form**: recommended, the arrow is always `type="button"` and never submits; whether the main part forwards `type`, `name`, `value` and `form` follows the `nph-button` (no source read).
- **Menu with no item or more than five**: recommended, with no item the arrow is disabled and a console warning shows in development; above five, everything renders and a console warning shows, because five is a usage guide (Figma, "Limits"). Carbon sets no maximum of items (https://carbondesignsystem.com/components/menu-buttons/usage/ ). No source read for the empty case.
- **Group disabled with the menu open**: recommended, the menu closes with no selection event and the focus follows item 12 (by analogy with Esc; no source read).
- **Forced colors** (Windows high contrast): recommended, test that the ring and the 2 px gap stay visible (no source read).
- **Width and orientation**: the group hugs its content; horizontal only in this version (Figma, "Limits").

## Why it is blocked
The `split-button/*` tokens came with this task and are on `v/5.0.0`: 5 alias tokens of the same function and 1 straight to the core by decision (`split-button/gap`; the evidence says why), with no new value in the core. Every piece it uses is done: `nph-icon` (DSA-03), `nph-button` (DSA-13 and later), `nph-tooltip` (DSA-42, DSA-48), `nph-dropdown-menu` (DSA-45), `nph-popover` (DSA-67, the precedent of the end alignment). It waits for DSA-110 (B1) and DSA-111 (B2).
