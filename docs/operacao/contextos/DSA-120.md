## Goal of this pass
Move the CSS of the older components from the semantic colors (`color/*`, `status/*`) to their own `<piece>/<property>` tokens, with the same look in light and dark, and draw an icon in the empty and error states of `nph-image`.
## Sources opened
- `docs/operacao/tarefas/DSA-120.md`, `docs/operacao/component-handoff.md`, `AGENTS.md`
- `src/tokens/generated/tokens.css` (the new tokens exist), the CSS, tests and sheet of each component listed in the task
## Changes
- CSS of 35 components reads its own tokens, `nph-option` through the existing `select/option-*` ones (all but the dot, which has no token, and `select/option-background-selected`, which the CSS has no read for). `nph-button` and `nph-badge` read the tokens by severity, emphasis and state; the icon-only `nph-button` reads the `icon-button/*` ones through added `data-nph-icon-only` blocks.
- Parents that redefined a semantic color for a child now redefine the child token: `nph-date-picker`, `nph-data-table`, `nph-toolbar`, `nph-notification` and `nph-sidebar`.
- `nph-image` draws `image`, `image-landscape` or `image-slash` on `image/illustration-background` in empty and error; the three icons are in `nph-icon` and in `design.md`.
- Contract tests, the sheets and the Metadata of the components above, the `nph-label` dictionary lines, the dictionary and the comments follow.
- Left as they are, with no token in the task table: `color/popover-foreground` of the panels, the panels of `nph-menubar`, the field and panel of `nph-command`, `color/accent` of the range preview in `nph-calendar`, `color/primary-hover` of the selected item in `nph-context-menu`, `color/secondary-foreground` in `nph-calendar`, `nph-scheduler` and `nph-navigation-menu`, `status/error` of the `nph-label` asterisk, `nph-dialog`, and the spinner color of `nph-command`, `nph-tree` and `nph-notification`. `nph-icon`, `nph-spinner` and `nph-collapsible` keep `currentColor` (code decision 1) and no CSS read of `collapsible/content-foreground`.
