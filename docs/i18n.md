# Idiomas do repositório

O Nephos publica sua **documentação de uso** em três idiomas: português do
Brasil, inglês e espanhol.

Esta nota é a convenção. Ela existe só em `pt-BR`, porque é instrução interna
para quem mantém o repositório, não documentação de uso.

## Idioma-fonte

**O português do Brasil é a fonte.** Toda regra nasce nele. As versões em inglês
e espanhol são traduções e **nunca decidem conteúdo**: se divergirem da fonte, a
fonte vence e a tradução está errada.

O arquivo **sem sufixo** é sempre o `pt-BR`.

## Convenção de nomes

```text
README.md          # pt-BR — fonte
README.en.md       # inglês
README.es.md       # espanhol

docs/tokens.md     # pt-BR — fonte
docs/tokens.en.md
docs/tokens.es.md
```

Todo documento de uso público futuro segue o mesmo sufixo. O nome do arquivo
não muda de idioma.

## O que é traduzido e o que não é

| Traduzido | Só em `pt-BR` |
|---|---|
| `README.md` | `AGENTS.md`, `CLAUDE.md`, `GOVERNANCA.md` |
| `docs/tokens.md` | `design.md`, `docs/decisoes-tecnicas.md` |
| Textos explicativos do Storybook | Esta nota, `docs/i18n.md` |
| Documentação publicada de componente | Figma, handoff e notas do vault |

**Identificadores técnicos nunca são traduzidos**, em nenhum idioma: as tags
`nph-*`, nomes de token, atributos, eventos, caminhos de arquivo, comandos,
nomes de pacote, código e testes.

## Rastreio de versão

Cada tradução começa com um comentário de rastreio, invisível na renderização:

```html
<!-- i18n: lang=en | source=README.md | source-sha256=<hash> -->
```

O `source-sha256` é o hash do **conteúdo do arquivo-fonte** no momento em que a
tradução foi feita. Quando alguém altera a fonte, o hash muda e a tradução passa
a estar declaradamente desatualizada.

Usamos o hash do conteúdo, e não o hash do commit, de propósito: o commit que
publica a fonte é o mesmo que publica a tradução, então uma referência a commit
seria circular.

```bash
npm run test:i18n
```

Reprova quando falta um par de idioma, quando um hash não bate com a fonte,
quando o seletor de idioma está ausente ou quando um identificador técnico
protegido não aparece igual nos três idiomas.

Depois de alterar a fonte e atualizar as traduções, grave os novos hashes:

```bash
npm run i18n:update
```

## Seletor de idioma

Os três arquivos de um mesmo documento abrem com a mesma linha de seletor, com o
idioma atual em negrito e os outros dois como link relativo.

## Regra de manutenção

- **Conteúdo público mudou:** atualize `pt-BR`, `en` e `es` **no mesmo PR**.
- **Regra técnica interna mudou:** altere só a fonte em `pt-BR`. Traduções só
  existem para documento público.
- **O PR não fecha** se um link entre idiomas quebrar, se uma tradução declarar
  hash diferente da fonte ou se um identificador técnico for traduzido.
- **Revisão humana:** antes de considerar publicada, uma pessoa lê a tradução e
  confere clareza e termos de produto. Tradução sem revisão humana entra como
  rascunho, não como versão vigente.

## Storybook

O Storybook tem um seletor de idioma na barra superior. Ele troca o **texto
explicativo** das páginas, não a estrutura: títulos de story, IDs e nomes de
componente permanecem estáveis para não quebrar links salvos.

Os textos ficam em `.storybook/i18n/`, um arquivo por idioma. Uma story **nunca**
é duplicada por idioma: ela lê o idioma escolhido e busca o texto no dicionário.
