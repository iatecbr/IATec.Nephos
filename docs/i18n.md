# Repository languages

Nephos publishes its **usage documentation** in three languages: English,
Brazilian Portuguese and Spanish.

This note is the convention. It exists only in English, because it is an
internal instruction for whoever maintains the repository, not usage
documentation.

## Source language

**English is the source** (P64, amendment of 06/10/2026). Every rule is born in
it. The Portuguese and Spanish versions are translations and **never decide
content**: if they diverge from the source, the source wins and the translation
is wrong.

The file **without a suffix** is always the English one.

## Naming convention

```text
README.md            # English — source
README.pt-BR.md      # Brazilian Portuguese
README.es.md         # Spanish

docs/tokens.md       # English — source
docs/tokens.pt-BR.md
docs/tokens.es.md
```

Every future public usage document follows the same suffix. The file name does
not change with the language.

## What is translated and what is not

| Translated | English only |
|---|---|
| `README.md` | `AGENTS.md`, `CLAUDE.md`, `GOVERNANCA.md`, `contributing.md` |
| `docs/tokens.md` | `design.md`, `docs/decisoes-tecnicas.md`, `docs/stories.md` |
| Explanatory texts of the Storybook | This note, `docs/i18n.md`, and `docs/operacao/` |
| Published component documentation | Specs in `fichas/` (the Figma board, in Portuguese, is the version for people) |

The Figma file and the team's vault stay in Portuguese; they are not part of
this repository.

**Technical identifiers are never translated**, in any language: the `nph-*`
tags, token names, attributes, events, file paths, commands, package names,
code and tests. Contract keys that are still in Portuguese (task, evidence and
spec keys, token modes) stay as they are until `DSA-15`.

## Version tracking

Each translation starts with a tracking comment, invisible when rendered:

```html
<!-- i18n: lang=pt-BR | source=README.md | source-sha256=<hash> | status=rascunho -->
```

The `source-sha256` is the hash of the **content of the source file** at the
moment the translation was made. When someone changes the source, the hash
changes and the translation becomes declaredly outdated.

We use the hash of the content, and not the hash of the commit, on purpose: the
commit that publishes the source is the same one that publishes the
translation, so a reference to a commit would be circular.

The `status` has two values: **`rascunho`** (draft) and **`revisado`**
(reviewed). Every translation is born `rascunho` and only becomes `revisado`
when whoever decides accepts the translation, with the check recorded — see
"Acceptance", below. A file in draft also carries the visible notice at the
top, for whoever reads the page and will never open this document.

```bash
npm run test:i18n
```

It fails when a language pair is missing, when a hash does not match the
source, when the language selector is missing, when the `status` is not one of
the two values, or when a protected technical identifier does not appear the
same in the three languages. A draft does **not** fail: the command only lists
which ones still await review.

On 06/10/2026 the source moved from Portuguese to English. No text was

`README.en.md` and `README.es.md` were written by AI and checked against the
Portuguese source by mechanical comparison — source hash, technical
identifiers, numerals and section structure — plus a content read. **Indiane
accepted that check on 31-08-2026 in place of a human read**, and the `status`
became `revisado`. Nobody read them line by line; whoever needs that guarantee
must know it. `docs/tokens.en.md` and `docs/tokens.es.md` were still
`rascunho` when the source moved. On 06-10-2026 the English `docs/tokens.md`
was checked against the accepted Portuguese text, and `docs/tokens.es.md`
against the English, in the same way — `npm run test:i18n`, technical

read — with no divergence of meaning. Indiane delegated the acceptance to that
check, as on 31-08-2026: the English source counts as accepted and the Spanish
file became `revisado`. The state of the source lives in this table, because a
source file has no tracking comment.

After changing the source and updating the translations, record the new hashes:

```bash
npm run i18n:update
```

## Language selector

The three files of the same document open with the same selector line, with the
current language in bold and the other two as relative links. The source starts
with `**English**`.

## Maintenance rule

- **Public content changed:** update `en`, `pt-BR` and `es` **in the same PR**.
- **Internal technical rule changed:** change only the English source.
  Translations exist only for public documents.
- **The PR does not close** if a link between languages breaks, if a
  translation declares a hash different from the source, or if a technical
  identifier is translated.
- **Acceptance:** before it counts as published, the translation is checked
  against the source and accepted by whoever decides. The minimum check is
  `npm run test:i18n` plus the comparison of technical identifiers, numerals
  and section structure. A translation that is not accepted goes in as a draft,
  not as the current version.

## Storybook

The Storybook has a language selector in the top bar. It changes the
**explanatory text** of the pages, not the structure: story titles, IDs and
component names stay stable so saved links do not break.

The texts live in `.storybook/i18n/`, one `.json` file per language
(`en.json`, `pt-BR.json`, `es.json`); `index.js` gathers the three. `en.json`
is the source and the default; `pt-BR.json` and `es.json` are translations, and
the selector shows English, Português (BR) and Español in that order. A story is
**never** duplicated per language: it reads the chosen language and looks the
text up in the dictionary.

The dictionary only holds text. When a sentence carries a number, it goes in
through a `{name}` marker — `"{found} of {total} icons"` — and the story fills
it with `format(text, { found, total })`, exported by `index.js`. The marker has
the same name in the three languages; only the text around it is translated.
JSON does not accept comments: the rules of each dictionary live in the comment
of `index.js`.

The dictionary keys are technical names and follow P64: `npm run test:naming`
checks the keys and leaves out the text and the `sidebar` subtree, whose keys
are story IDs.

*Dictionaries in JSON by Indiane's decision on 05-10-2026, from a suggestion by
Mauro. Until then they were `.js`.*
